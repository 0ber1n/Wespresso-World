WESPRESSO WORLD — CTFd WHALE SETUP GUIDE
=========================================
Per-student isolated instances on a LAN (30+ students)


OVERVIEW
--------
CTFd Whale is a plugin that automatically spins up a fresh Wespresso World
container per student when they click "Start Instance" in CTFd.

Architecture:

    Students (LAN)
         ↓
    CTFd (host:8000)          ← scoreboard + challenge tracking
         ↓ spawns via Whale
    Docker                    ← one Wespresso World container per student
         ↓
    Student 1 → port 1338
    Student 2 → port 1339
    Student 3 → port 1340
    ... and so on

RAM estimate: each container uses ~256-512MB
30 students = 8-15GB RAM needed on the host machine


PREREQUISITES
-------------
- Docker + Docker Compose installed
- Your Wespresso World repo cloned and working
- Host machine on the LAN with a static IP (e.g. 192.168.1.100)
- At least 16GB RAM on the host machine recommended for 30+ students


STEP 1 — CLONE THE WHALE PLUGIN
--------------------------------
From your project root:

    mkdir -p ctfd/plugins
    git clone https://github.com/CTFd/ctfd-whale ctfd/plugins/ctfd-whale


STEP 2 — UPDATE docker-compose.yml
------------------------------------
Add the following to your CTFd service in docker-compose.yml:

    ctfd:
      image: ctfd/ctfd
      restart: always
      ports:
        - "8000:8000"
      environment:
        - UPLOAD_FOLDER=/var/uploads
        - DATABASE_URL=mysql+pymysql://ctfd:${CTFD_DB_PASS:-ctfd}@ctfd-db/ctfd
        - REDIS_URL=redis://ctfd-redis:6379
        - WORKERS=1
        - LOG_FOLDER=/var/log/CTFd
        - ACCESS_LOG=-
        - ERROR_LOG=-
      volumes:
        - ctfd-uploads:/var/uploads
        - ctfd-logs:/var/log/CTFd
        - /var/run/docker.sock:/var/run/docker.sock          # Gives CTFd access to Docker
        - ./ctfd/plugins/ctfd-whale:/opt/CTFd/CTFd/plugins/ctfd-whale  # Mounts Whale plugin
      depends_on:
        ctfd-db:
          condition: service_healthy
        ctfd-redis:
          condition: service_started
      networks:
        - lab

Full docker-compose.yml should look like this:

    services:

      wespresso-frontend:
        build:
          context: ./frontend
        ports:
          - "31337:80"
        networks:
          - lab

      wespresso-api:
        build:
          context: ./backend
        ports:
          - "1337:8080"
        networks:
          - lab

      ctfd:
        image: ctfd/ctfd
        restart: always
        ports:
          - "8000:8000"
        environment:
          - UPLOAD_FOLDER=/var/uploads
          - DATABASE_URL=mysql+pymysql://ctfd:${CTFD_DB_PASS:-ctfd}@ctfd-db/ctfd
          - REDIS_URL=redis://ctfd-redis:6379
          - WORKERS=1
          - LOG_FOLDER=/var/log/CTFd
          - ACCESS_LOG=-
          - ERROR_LOG=-
        volumes:
          - ctfd-uploads:/var/uploads
          - ctfd-logs:/var/log/CTFd
          - /var/run/docker.sock:/var/run/docker.sock
          - ./ctfd/plugins/ctfd-whale:/opt/CTFd/CTFd/plugins/ctfd-whale
        depends_on:
          ctfd-db:
            condition: service_healthy
          ctfd-redis:
            condition: service_started
        networks:
          - lab

      ctfd-db:
        image: mariadb:10.11
        restart: always
        environment:
          - MYSQL_ROOT_PASSWORD=${CTFD_DB_ROOT_PASS:-ctfd}
          - MYSQL_USER=ctfd
          - MYSQL_PASSWORD=${CTFD_DB_PASS:-ctfd}
          - MYSQL_DATABASE=ctfd
        volumes:
          - ctfd-db:/var/lib/mysql
        healthcheck:
          test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
          interval: 10s
          timeout: 5s
          retries: 5
        networks:
          - lab

      ctfd-redis:
        image: redis:7-alpine
        restart: always
        volumes:
          - ctfd-cache:/data
        networks:
          - lab

    networks:
      lab:
        driver: bridge

    volumes:
      ctfd-uploads:
      ctfd-db:
      ctfd-cache:
      ctfd-logs:


STEP 3 — BUILD AND TAG YOUR APP IMAGE
---------------------------------------
Whale needs a locally available Docker image to spin up per student.
Build and tag it from your project root:

    docker build -t wespresso-world:ctf ./backend

Verify it built:

    docker images | grep wespresso-world


STEP 4 — START THE STACK
--------------------------
    docker compose up -d

Watch CTFd start up:

    docker compose logs -f ctfd

Wait for "Listening at: http://0.0.0.0:8000" before proceeding.


STEP 5 — COMPLETE CTFd FIRST-RUN WIZARD
-----------------------------------------
Open http://localhost:8000 in your browser.

    CTF Name:        Wespresso World CTF
    Admin user:      (your choice — write it down)
    Admin password:  (your choice — write it down)
    Mode:            Users
    Start time:      leave blank
    End time:        leave blank

Click Finish/Save.


STEP 6 — DISABLE EMAIL VERIFICATION
--------------------------------------
    Admin Panel → Config → Settings → Email
    - Mail Server:    leave blank
    - Verify Emails:  OFF

    Admin Panel → Config → Settings → Registration
    - Registration Visibility: Private  (you create accounts manually)


STEP 7 — CONFIGURE WHALE
--------------------------
    Admin Panel → Whale → Settings

    Docker API URL:       unix:///var/run/docker.sock
    Gateway IP:           192.168.1.100       ← replace with your actual LAN IP
    Starting Port:        1338
    Max Container Time:   3600                ← 1 hour per student (adjust as needed)
    Max Container Count:  35                  ← set slightly above student count

To find your LAN IP:

    hostname -I | awk '{print $1}'


STEP 8 — CREATE A DYNAMIC DOCKER CHALLENGE
--------------------------------------------
    Admin Panel → Challenges → New Challenge

    Type:           Dynamic Docker       ← appears after Whale is installed
    Name:           (your challenge name)
    Docker Image:   wespresso-world:ctf
    Port:           8080
    Points:         (your choice)
    Description:    Your instance is at http://<host>:<port>
                    (CTFd fills in <host> and <port> automatically per student)

Repeat for each challenge that needs an isolated instance.


STEP 9 — CREATE STUDENT ACCOUNTS
----------------------------------
Since registration is private, create accounts manually:

    Admin Panel → Users → New User

    Username:   student1
    Password:   (give to student)
    Email:      fake@lab.local  (email is disabled so this doesn't matter)

Tip: you can script this with the CTFd API if you have a class roster:

    curl -X POST http://localhost:8000/api/v1/users \
      -H "Authorization: Token YOUR_ADMIN_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"name":"student1","password":"pass123","email":"s1@lab.local","type":"user"}'

Get your admin token from:
    Admin Panel → Settings → (your username) → API Access Tokens → Generate


WHAT STUDENTS EXPERIENCE
--------------------------
1. Connect to your LAN
2. Go to http://192.168.1.100:8000  (your host IP)
3. Log in with credentials you gave them
4. Click a challenge → click "Start Instance"
5. CTFd spins up their own Wespresso World container
6. They get a unique URL like http://192.168.1.100:1338
7. They work through the challenge against their own isolated instance
8. Instance auto-destroys after the time limit


MANAGING THE LAB DURING A SESSION
-----------------------------------
Monitor running student containers:

    docker ps | grep wespresso

Check resource usage:

    docker stats

Manually kill a student container if needed:

    docker stop <container_id>

Restart CTFd without losing scores:

    docker compose restart ctfd


STOPPING AND RESETTING
-----------------------
Stop all services (keeps data):

    docker compose down

Stop and wipe ALL data (scores, accounts, CTFd DB):

    docker compose down -v

Wipe only student challenge containers (keep CTFd running):

    docker ps -q --filter "ancestor=wespresso-world:ctf" | xargs docker stop


TROUBLESHOOTING
---------------
Whale not appearing in Admin Panel
    → CTFd needs a full restart after the plugin is mounted:
        docker compose restart ctfd

Student containers not spawning
    → Check Docker socket is accessible:
        docker compose exec ctfd ls /var/run/docker.sock
    → Check Whale logs:
        docker compose logs ctfd | grep -i whale

Port conflicts
    → If 1338+ ports are in use, change Starting Port in Whale settings

Out of memory
    → Check usage:   docker stats
    → Limit per-container RAM in your Dockerfile or compose:
        deploy:
          resources:
            limits:
              memory: 512m

CTFd won't start
    → Wait for MariaDB health check (up to 60s on first boot)
    → Check: docker compose logs ctfd-db

Lost admin password
    docker compose exec ctfd flask shell
    >>> from CTFd.models import Users
    >>> u = Users.query.filter_by(type='admin').first()
    >>> u.password = 'newpassword'
    >>> from CTFd import db
    >>> db.session.commit()


SERVICE MAP
-----------
Wespresso World frontend    http://<host>:31337
Wespresso World API         http://<host>:1337/api/v1
CTFd platform               http://<host>:8000
Student instances           http://<host>:1338, :1339, :1340 ...
MariaDB                     internal only (ctfd-db:3306)
Redis                       internal only (ctfd-redis:6379)

Replace <host> with your machine's LAN IP for students to access remotely.
For local testing use localhost or 127.0.0.1.
